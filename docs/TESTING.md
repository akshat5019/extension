# Manual Chrome checks

Automated tests exercise bundled code with actual Chromium DOM/IndexedDB and adapted extension APIs. Managed cloud Chromium prevents native installation; these checks need your unmanaged browser.

1. Build/load dist, or extract the compiled ZIP and Load unpacked its manifest folder. Inspect the extension Errors page and background service-worker console. Refresh old portal tabs when upgrading.
2. Import a PDF from both the popup and **Open workspace** tab; confirm review and saving work in both. Import example-people.csv, select each person in turn, and fill a standard registration/application. Verify no existing values are overwritten and no submit is clicked. Undo before switching people.
   Test **Scan & fill** after explicit profile selection. Change a form step after staging a missing answer; quick fill must rescan and leave that old answer behind. Change the selected profile in another workspace and verify the stale revision stops filling. Verify reader chunks are loaded only for the chosen format and standard DOCX parsing runs in the worker. Upgrade a version 1 database without resetting profiles; search/duplicate checks, sources, revisions, documents and settings must remain available.
3. Upload a text-based multi-person PDF and a DOCX. Verify person boundaries and incomplete-page warnings. Try a scanned PDF and check the no-text error. Import XLSX phones formatted as text.
   Also import a resume with an unlabelled name heading and education/project sections. Review the suggested first/middle/last split, select the saved person, and fill visible full/first/last name fields without typing them. Test an existing full-name-only profile and explicitly supplied compound name parts. Attach required resume files separately; scan again after the portal advances to its name fields.
   Try a Data Analyst resume with a large name heading, including a single-word name, and a PDF whose stored object order puts contact/sidebar text before the heading. For ambiguous names, verify the **Use [name]** suggestions populate the selected name and that switching suggestions refreshes all name parts before confirmation. Verify names are not taken from the filename/email username and distinct people are not combined.
   Try inline contact rows (`Akshat Sharma | Data Analyst`, followed by `akshat@example.com | Pune, India`) and DOCX labels on separate paragraphs. Verify the ready-for-autofill summary, names, email, city and country without retyping. Confirm import, reopen the extension, select the person, scan and fill all six fields. Verify employer/school locations are excluded, conflicts stay for review, and absent countries are not inferred from phone numbers.
4. Import changed/new people, review duplicates/conflicts, choose create/update/skip and confirm. Try the identical file again; verify there are no repeat writes. Try two open workspace windows editing the same profile; the stale revision must be rejected.
5. Enter missing information, verify it is not stored before confirmation, then save to the correct selected person. Select another person and verify their fields remain unchanged. Keep both conflicting values and verify ambiguous values are withheld from autofill.
6. Close and restart Chrome, reopen the extension, and search/select the saved people. Confirm IndexedDB persistence and absence of unsolicited automatic filling. Back up before uninstalling or changing extension IDs.
7. Try native activeTab permission and optional hostname access/revocation. Test restricted Chrome pages, embedded/custom forms, changed labels, invalid inputs, Next/Continue and new tabs. Rescan each step; unsupported controls must remain manual.
   Test adjacent labels/ATS identifiers, open shadow components (including display:contents hosts), and same-origin iframes with native selects, dates and separate radio groups. Confirm trusted edits from those controls can be saved after review and undo preserves them. Cross-origin/sandboxed frames and custom dropdowns must remain untouched with an explanation. Changing an embedded document/URL must invalidate its scanned fields. Verify referee/emergency-contact names never receive the selected person's own name automatically.
8. Test individual delete, confirmed merge, private JSON export/reimport and Delete all data. If upgrading 1.x, verify one review-needed legacy person and exported legacy answer archive. Confirm registration retirement.
9. On a Chrome build exposing LanguageModel, explicitly prepare the local model and test ambiguous free-form text. Verify review is mandatory, quoted values match the source, and no personal-data network requests are made. The cloud test only validates the provider contract with a simulated model, not native API/model quality.

Never disable antivirus, managed extension policy or CAPTCHA protections to perform these checks. Live portal compatibility and native browser permissions are separate from the automated fixture results.
